# Day 043 Postmortem — Karuta Mooncall Duelist

## Summary

Day 043 adds **Karuta Mooncall Duelist**, a portrait-first 2D karuta memory-reaction arcade game served at `/karuta/`. The game contrasts Day 042's vertical 3D cedar climb with a low moonlit card-table duel: reader cues, card scanning, memory marks, card locks, decisive sweeps, rival-hand timing, reshuffle pressure, Mooncall Focus previews, localStorage best score, and WebAudio cues initialized after the Start gesture.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and the code-isolation rule. No visible Day 043 file progress appeared while the controller continued, so the controller took ownership of the Day 043 app/release/alias files from the archived prompt and generated Imagegen2 assets directly. A separate QA/review subagent was dispatched after implementation for an independent pass.

## Issues found and fixed during QA

- Route smoke initially failed because the probe used ambiguous `getByText('Scan Fan')` selectors that matched tutorial and pause text. The QA probe was fixed to use button roles, then rerun.
- Prompt-reference pitfall hit exactly as documented: `waitForSelector('#pauseOverlay.hidden')` waits for visibility and timed out on a correctly hidden overlay. The probe was fixed to use `waitForFunction(() => classList.contains('hidden'))`.
- Mobile 390×844 controls initially extended 3.5px below the viewport. The mobile CSS reduced the canvas from 286px to 276px and tightened the 4-column control grid padding/gap; rerun passed with controls bottom at 832.47px.
- Removed a responsive rule that hid the required `Risk` HUD chip under 400px; rerun confirmed all required HUD chips are visible and non-zero size.

## Notes for future runs

- Karuta/card-recognition prompts need text-labeled controls and large abstract symbols; generated card art should not be trusted for readable text.
- For 13 controls at 390×844, a 4-column grid works if canvas and helper heights are tightly budgeted. Always check the actual controls bottom, not Playwright auto-click success.
- Keep route-smoke selectors role-based when tutorial/pause text repeats control names.

## Caveats

- The karuta simulation uses abstract romanized/card-trait matching rather than real classical poem text, intentionally avoiding tiny unreadable text and generated-text artifacts.
- Generated helper/piece/icon assets use warm parchment backgrounds rather than true transparent alpha; they were inspected and used in contexts where the background is visually acceptable.
