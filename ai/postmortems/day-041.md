# Day 041 Postmortem — Kinoko Mycelium Glowkeeper

## Summary

Day 041 adds **Kinoko Mycelium Glowkeeper**, a portrait-first 2D mycelium network routing puzzle served at `/kinoko/`. The game uses a bioluminescent cedar forest floor, Imagegen2 generated kodama/background/pieces/icon art, a Canvas mycelium board, selectable mushroom-root nodes, Rotate Branch, Flip Flow, Pulse Nutrients, Mist Spores, Shoo Beetles, Lock Route, Harvest Glow, Bloom Focus previews, dew/dryness/beetle pressure, localStorage best score, and WebAudio cues initialized after the Start gesture.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and the code-isolation rule. The controller generated the Imagegen2 assets and took ownership of the Day 041 app/release/alias files after detecting concurrent subagent shell writes, then reconciled by using the controller-owned HTML/CSS/JS implementation consistently across app, immutable release, and public alias.

## Code-isolation confirmation

No previous game implementation source was intentionally opened, inspected, copied, diffed, grepped, or adapted during Day 041 planning, implementation, QA, or validation. Previous days were used only through `src/data/games.ts`, `release/manifest.json`, recent prompts/postmortems, and screenshots/metadata for variety planning before `prompts/day-041.md` was written. Day 041 HTML/CSS/JS was written for `apps/day-041-kinoko-mycelium-glowkeeper/` from the archived Day 041 prompt, Imagegen2 assets, and general browser/Canvas/WebAudio game knowledge, then copied into `release/games/041/` and `/kinoko/`.

## Issues found and fixed

- First prompt HTML render created direct nested-list DOM (`ul > ul` / `ol > ul`) from indented Markdown. The controller regenerated Day 041 prompt pages with a non-nested semantic list renderer and reran route smoke; prompt DOM passed.
- Concurrent implementation subagent output touched the Day 041 app shell while the controller was taking ownership. The controller treated the controller implementation as the owner and synced matching HTML/CSS/JS into app/archive/alias paths to avoid mixed shell/module contracts.
- Generated assets use warm parchment backgrounds rather than true transparent alpha. They were inspected and integrated in helper/icon/support-art contexts where the background is acceptable; the interactive mycelium graph/pulses/beetles are rendered directly for mechanical clarity.

## Lessons for future prompts

- Markdown prompt renderers should avoid direct nested list output unless they build proper nested lists inside `<li>` elements; flattening indented prompt bullets is safer than shipping invalid prompt DOM.
- Organic network puzzles benefit from stable text-labeled controls (`Rotate Branch`, `Pulse Nutrients`, `Mist Spores`, `Shoo Beetles`) plus visible pulse path animation so QA can verify named mechanics without relying on color alone.
- For 14-button mobile games, a 7-column two-row control grid can keep all controls in the 390×844 first viewport, but labels must be short and stable.

## Caveats

- The mycelium simulation is arcade/schematic rather than a biological network model, but node selection, branch orientation, one-way flow, nutrient pulses, wetness, beetles, harvest, and Bloom Focus previews have visible mechanical effects.
- The gallery screenshot is a dark forest-board view by design; generated support assets give the day a distinct visual identity while the Canvas layer keeps gameplay readable.
