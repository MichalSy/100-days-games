# Day 034 Postmortem — Temari Thread Orbit Weaver

## Summary

Day 034 adds **Temari Thread Orbit Weaver**, a portrait-first 3D spherical embroidery puzzle served at `/temari/`. The game uses a self-contained Three.js route with a lacquered temari sphere, selectable guide rings and pearl pins, silk-color wrapping, tension/tangle management, pearl intersection locking, undo, Kagome Focus preview, persistent best score, and WebAudio feedback initialized after the Start gesture.

## Issues found and fixed

- Initial controller smoke found a mismatched canvas ID / DOM contract in an early draft, causing Three.js renderer initialization to fail. Fixed by aligning HTML IDs with `game.js` and re-copying app files into immutable and alias routes.
- Hidden overlays were still visually present because the stylesheet lacked a `[hidden]` rule. Added `[hidden] { display: none !important; }`.
- Mobile first-viewport initially lacked room for all controls. Rebalanced mobile grid rows so the 3D stage, status, and every primary control fit inside 390×844 without forced landscape.
- Prompt button was only a topbar link; added a control-grid Prompt button so the route smoke and mobile controls expose the prompt affordance.
- Commission goal spans ran together visually; added inline spacing and completion styling.

## Lessons for future prompts

- For 3D standalone routes, keep the HTML/JS DOM contract explicit in the archived prompt: exact canvas ID, overlay IDs, audio toggle IDs, and control IDs should be named before implementation.
- Mobile 3D games need a pre-budgeted vertical grid. A playable 390×844 layout should reserve no more than ~60px topbar, ~54px HUD, ~80px objective card, 250–380px stage, ~38px status, and the rest for controls.
- Text controls remain more reliable than tiny icon-only controls for complex 3D mechanics on phones.
- Always run a route-level smoke before copying screenshots; gallery screenshots can accidentally capture `prompt.html` if a smoke script navigates there after gameplay.

## Caveats

- This day uses Imagegen2 PNGs plus vendored Three.js assets, so the route is larger than simpler 2D days. The Docker/static smoke and route smoke verified the assets serve correctly.
- Desktop page can scroll when the 1280×900 viewport includes all controls, but the required mobile portrait layout fits without page scroll.
