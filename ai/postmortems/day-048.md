# Day 048 Postmortem — Kiriko Lantern Prism Cutter

## Summary

Day 048 shipped a mobile-first 3D Edo-kiriko glass-cutting arcade/puzzle game at the public route `/kiriko/`. The game uses Imagegen2 atelier/helper/pieces/icon assets, vendored Three.js modules, WebAudio feedback, a debug handle for deterministic QA, and a portrait-first control grid for rotating/tilting a faceted glass lantern, scoring/deepening grooves, cooling, polishing, shifting lantern beams, catching caustics, repairing hairlines, and triggering Kiriko Prism Illumination.

## What went well

- The archived prompt was created first at `prompts/day-048.md`, then implementation proceeded from that prompt.
- The visual identity is clearly different from the preceding sky/terrace/bug day: dark lacquer workbench, ruby/cobalt cut glass, brass tools, lantern caustics, and a 3D rotating glass stage.
- The route-specific Playwright probe verified menu/tutorial terms, start flow, WebAudio initialization, named controls, state-changing mechanics, pause/resume, restart, prompt-page DOM, and a forced end-state/blessing path.
- The mobile 390x844 probe kept HUD, commission card, 3D stage, helper, and all controls inside the first viewport with no page scroll. Touch targets measured above 44px.
- Prompt HTML is semantic HTML with a back-to-game link and DOM checks for malformed lists, raw Markdown dumps, nested-list corruption, and `<code><strong>` glob corruption.

## Issues and recovery

- The controller had to finish and reconcile the implementation directly because the implementation subagent summary was too terse to trust as a complete handoff.
- The first helper asset copy carried a parchment/white background, which created a visible rectangle in gameplay. The optimized helper PNG was alpha-cleaned, recropped into a transparent 512px canvas, copied back to app, immutable release, and public alias folders, and re-inspected visually.
- The first desktop gallery screenshot was captured after a forced blessing overlay, so it was unsuitable as a gallery thumbnail. The route smoke was changed to capture active gameplay before forcing the terminal state, then the desktop screenshot was recopied to `release/games/048/screenshot.png` and `release/kiriko/screenshot.png`.
- Initial mobile layout had all controls visible but slightly exceeded 390x844. The mobile CSS now uses a compact six-column control grid, fixed portrait stage row, and tighter HUD/commission spacing; the final metric is `scroll=844`, `innerHeight=844`, `maxButtonBottom=838`, `minButton=62.7`, `stage=220`.
- The public alias originally received a duplicated `assets/source/` tree during release copying. That was removed; source assets are archived only under `release/games/048/assets/source/`.

## Follow-up improvements

- Keep taking gallery thumbnails before forced terminal overlays; terminal-state probes are useful but should not drive gallery imagery.
- For character/helper assets, explicitly require transparent cutout or perform alpha cleanup before first route smoke to avoid white-box artifacts.
- Mobile prompts with many controls should default to compact 6-column command grids or prioritize visible short labels from the start.
