# Day 037 Postmortem — Kingyo Poi Festival Scooper

## Summary

Day 037 adds **Kingyo Poi Festival Scooper**, a portrait-first 2D goldfish-scooping dexterity arcade game served at `/kingyo/`. The game uses a shallow lantern-lit water tank, Imagegen2 generated fish/background/helper/icon assets, direct drag poi-net controls, Tilt Net, Dip/Lift timing, Swap Poi paper safety, Bowl Nudge, Festival Focus, paper wetness/turbulence/order feedback, localStorage bests, and WebAudio cues initialized after the Start gesture.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and code-isolation rule. The subagent created the initial Day 037 asset and index scaffold; the controller took ownership of the incomplete file set, completed the game logic/CSS/release integration, alpha-cleaned the fish sprite sheet, ran route QA, and performed final validation/deployment.

## Code-isolation confirmation

No previous game implementation source was intentionally opened, inspected, copied, diffed, grepped, or adapted during Day 037 planning, implementation recovery, QA, or validation. Previous days were used only through `src/data/games.ts`, `release/manifest.json`, recent prompts/postmortems, and screenshots for variety planning before `prompts/day-037.md` was written. Day 037 HTML/CSS/JS was written for `apps/day-037-kingyo-poi-festival-scooper/` from the archived Day 037 prompt and general browser/canvas/WebAudio game knowledge, then copied into `release/games/037/` and `/kingyo/`.

## Issues found and fixed

- The implementation subagent produced a partial scaffold/assets without `styles.css`, `game.js`, metadata, prompt pages, screenshots, or postmortem. Controller completed the missing app/release/alias files from the archived prompt.
- A first route smoke caught a JavaScript startup error from an undefined `pauseButton` reference; controller corrected it to use the existing pause element and resynced app/archive/alias `game.js`.
- The generated fish sprite sheet initially rendered as black rectangular cells around fish. Controller alpha-cleaned the runtime fish sheet and re-ran desktop/mobile smoke/screenshots.
- The first prompt renderer pass allowed Markdown bold conversion inside inline code containing `**` globs. Controller regenerated prompt HTML with code spans protected before bold conversion; DOM probe now reports malformed/code-strong count `0`.

## Lessons for future prompts

- For generated sprite sheets on dark backgrounds, include explicit alpha-cleaning/flood-fill cleanup in the asset pipeline before first route screenshots.
- Keep a narrow route smoke that exercises direct drag/touch mechanics, not only button clicks, for dexterity/tap games.
- Prompt HTML rendering should protect inline code before applying emphasis to prevent recurring `**` glob corruption.

## Caveats

- The fish-scooping physics are arcade/schematic rather than a fluid simulation, but all required controls have visible mechanical effects and readable paper/turbulence/order feedback.
- The helper and icon assets use clean parchment backgrounds instead of true transparent alpha; they were inspected and integrated inside cards/buttons where that background is acceptable.
