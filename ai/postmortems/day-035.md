# Day 035 Postmortem — Hashi Tanuki Bridgewright

## Summary

Day 035 adds **Hashi Tanuki Bridgewright**, a portrait-first 2D bridge-building physics puzzle served at `/hashi/`. The game uses a side-view dusk mountain stream, large bridge sockets, bamboo beams, rope braces, stone piers, stress/budget/current feedback, tanuki porter load-test animation, repair/remove actions, Survey Focus load-path preview, WebAudio cues after the Start gesture, and persistent best-score/Grand Crossing state.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and code-isolation rule. The controller observed a partial Day 035 file set and took ownership of the remaining implementation/release/QA work to avoid publishing an incomplete game. An independent QA/review subagent was also dispatched; controller route smoke and full local validation below are the authoritative pre-push evidence.

## Issues found and fixed

- The first route-smoke helper script used an absolute CommonJS Playwright import incorrectly; fixed the script before using it as evidence.
- The first mobile smoke flagged HUD `Pause`/`Audio On` controls under 44px; mobile CSS now keeps mini controls at 44px+.
- The first active screenshot had clipped Survey Focus canvas text because `textAlign` was left in `center` state after drawing node labels; fixed `drawFocus()` to set `textAlign='left'` before rendering the label.
- A post-deploy prompt smoke found Markdown `**` glob text rendered as `<strong>` inside `<code>` in the Day 035 prompt page; fixed both immutable and alias prompt HTML so `release/games/001/**` through `release/games/034/**` stays literal.
- Controller synchronized app, immutable release, and public alias copies after each CSS/JS fix.

## Lessons for future prompts

- Side-view mobile games benefit from a route-smoke capture that intentionally performs a few actions before screenshotting, otherwise gallery cards can look like empty setup screens.
- Canvas render helpers should reset all drawing state they depend on (`textAlign`, line dash, transform), not assume previous draw calls left defaults intact.
- For construction games, the prompt should explicitly state whether material buttons place immediately or select a tool plus separate Place action; immediate placement worked here but should be specified earlier next time.

## Caveats

- The bridge physics are intentionally arcade/simplified rather than a full rigid-body solver, but all required controls have visible mechanical effects and stress/load feedback.
- The helper and icon assets use clean parchment backgrounds instead of transparent alpha. They were inspected and integrated inside cards/buttons where the background is acceptable.
