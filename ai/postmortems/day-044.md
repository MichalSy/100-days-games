# Day 044 Postmortem — Kakigori Prism Shavewright

## Summary

Day 044 adds **Kakigori Prism Shavewright**, a portrait-first 3D dessert-sculpting arcade game served at `/kakigori/`. It deliberately follows Day 043's 2D karuta table with a real 3D spatial game: rotating a translucent shaved-ice mound, selecting height bands, carving syrup channels, pouring colored syrup, placing toppings, freezing routes, draining puddles, and using Prism Focus to preview flow and melt risk.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and the code-isolation rule. No Day 044 file progress was visible when the controller inspected the worktree, so the controller took ownership to avoid stalling the daily run. Generated Imagegen2 assets were created and inspected directly by the controller, then integrated into the app, immutable release, and public alias. A separate route-smoke/QA pass was then run against the actual `/kakigori/` route.

## Code-isolation confirmation

Previous days were used only through `src/data/games.ts`, `release/manifest.json`, recent prompts/postmortems, and screenshots/metadata for variety planning before `prompts/day-044.md` was written. Day 044 HTML/CSS/JS was written for `apps/day-044-kakigori-prism-shavewright/` from the archived Day 044 prompt, Imagegen2 assets, and general browser/Three.js/WebAudio game knowledge, then copied into `release/games/044/` and `/kakigori/`.

## Issues found and fixed during QA

- First control-effect probe placed a topping after Tilt Spoon moved to a face without a stable groove, so the topping visibly slid but did not increment the successful topping count. The QA sequence was corrected to Freeze Mist before Place Topping for the success-path check while retaining the slide behavior as a valid failure feedback.
- Pause overlay initially lacked the literal “Controls summary” wording expected by the QA checklist. The pause text was updated in app, immutable release, and public alias before rerunning route smoke.
- Extra unneeded non-minified Three.js files briefly appeared in the Day 044 assets; they were removed, keeping only `three.module.min.js` and matching `three.core.min.js` in each served location. Route smoke passed again after removal.

## Notes for future runs

- Dessert/sculpting prompts benefit from success-path QA sequencing: create a stable surface (carve or mist) before treating topping placement as a successful topping, otherwise a deliberate slide-failure state can be mistaken for a missing control effect.
- For 16 controls at 390×844, a 4-column control grid with 44px targets and a ~310px stage can fit without body scrolling, but only if HUD chips are compact and no prompt-required chip is hidden.
- Generated icon sheets may include decorative glyph-like marks; keep runtime controls text-labeled and avoid relying on generated text for gameplay meaning.

## Caveats

- The helper/stall/piece/icon generated assets use clean parchment/scene backgrounds rather than true transparent alpha. They were inspected and are used in contexts where those backgrounds are visually acceptable.
- The 3D syrup/mound mechanics are intentionally stylized Three.js geometry rather than a full fluid simulation; visible route, groove, melt, topping, puddle, and focus state changes satisfy the prompt’s game-feel requirements.
