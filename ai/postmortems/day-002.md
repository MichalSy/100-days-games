# Day 002 postmortem — Clockwork Cloud Courier

## What worked

- Generated the archived Day 002 prompt first at `prompts/day-002.md`, then implemented from that prompt.
- Built a self-contained static browser game with title/menu, tutorial, route difficulty selection, keyboard and mobile drag controls, boost, wind lanes, delivery objectives, hazards, pause, restart, results, local best score, stars, mastery checklist, and Golden Dispatch celebration.
- Created both release archive output under `release/games/002/` and the public route alias under `release/002/`.
- Copied the prompt to `release/games/002/prompt.md` and rendered `release/games/002/prompt.html`.
- Image assets were produced and archived under `release/games/002/assets/source/`, with playable copies under `release/games/002/assets/`.
- Local validation passed after fixing a Docker/static smoke permission issue.

## Issues

- The first Docker/static smoke failed with Nginx `403 Forbidden` because generated/copy output files under Day 002 were not world-readable inside the container (`rw-------`).
- Fixed by normalizing permissions on the Day 002 app, prompt, and release outputs before rerunning build and Docker/static smoke.
- The implementation subagent timed out before returning its final report, so final validation, smoke checks, permission fix, and publication were completed in the controller session.

## Improvements for future days

- Add an automated permission normalization step to `scripts/ensure-release-structure.mjs` or the nightly implementation checklist so Docker/static smoke cannot fail on unreadable generated files.
- Add per-day Playwright smoke coverage for the newest route, not only the gallery, including menu/tutorial/pause/restart and mobile viewport checks.
- Add release validation checks that compare `prompts/day-NNN.md` and `release/games/NNN/prompt.md`, verify prompt HTML exists, and verify screenshot/assets are non-empty.
