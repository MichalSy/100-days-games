# Day 036 Postmortem — Takumi Karakuri Gearwright

## Summary

Day 036 adds **Takumi Karakuri Gearwright**, a portrait-first 3D layered clockwork routing puzzle served at `/takumi/`. The game uses vendored Three.js with near/middle/far gear plates, selectable axles, gear sizes, direction flipping, depth couplers, oil timing, Test Crank animation, torque/jam/bell feedback, Takumi Focus affordance, persistent best-score state, and WebAudio cues initialized after the Start gesture.

A fresh implementation subagent was dispatched with only the repo path, day number, archived prompt path, validation/publish rules, and the code-isolation rule. The controller observed partial Day 036 files, waited for the new game/release route, then took ownership of metadata, QA fixes, route smoke, screenshot capture, final validation, and deployment preparation.

## Code-isolation confirmation

No previous game implementation source was intentionally opened, inspected, copied, diffed, grepped, or adapted during Day 036 planning, implementation recovery, QA, or validation. Previous days were used only through `src/data/games.ts`, `release/manifest.json`, recent prompts/postmortems, and screenshots for variety planning before `prompts/day-036.md` was written. Day 036 HTML/CSS/JS was written for `apps/day-036-takumi-karakuri-gearwright/` from the archived Day 036 prompt and general browser/Three.js/WebAudio game knowledge, then copied into `release/games/036/` and `/takumi/`.

## Issues found and fixed

- Metadata and postmortem were missing from the partial implementation; controller added Day 036 to `src/data/games.ts` and `release/manifest.json` and wrote this postmortem.
- The Gear Size control updated to “Gear: Small/Medium/Large”, which caused route-smoke control verification to miss the named prompt requirement. Controller changed it to “Gear Size: …” in app, immutable release, and alias copies.
- Mobile topbar `Audio` and `Pause` buttons were 38px high. Controller added a mobile media-rule override to keep topbar controls at 44px+.
- WebAudio initialized but lacked a debug handle for verification. Controller added `window.__day036Audio = { ctx, enabled }` after user-gesture initialization in app, immutable release, and alias copies.
- Prompt HTML contained the recurring Markdown `**` glob corruption inside `<code>` for `release/games/001/**` through `release/games/035/**`; controller patched immutable and alias prompt pages.
- Final desktop route-smoke screenshot was copied into both screenshot paths for gallery use.

## Lessons for future prompts

- Keep button labels stable when the prompt names a control. Dynamic state can be appended, but the named mechanic should stay in the label (for example `Gear Size: Medium`).
- Route smoke should tolerate intentionally disabled ability buttons while separately verifying their visible presence and enabled behavior when charged.
- For Three.js/WebAudio days, include a required debug audio handle in the prompt so QA can assert user-gesture audio initialization without guessing.
- Prompt renderers still need a stronger inline-code escape path for glob patterns containing `**`.

## Caveats

- The gear physics are arcade/schematic rather than a full tooth-by-tooth simulation, but the layer/axle/gearing/coupler/oil/test controls have visible mechanical effects and readable torque/jam/bell feedback.
- The generated assets use clean illustrated backgrounds rather than true transparent sprite cutouts; they were inspected and integrated inside cards/stage backgrounds where that is acceptable.
