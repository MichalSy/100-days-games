# Day 050 Postmortem — Kagura Mask Star Dancer

## Summary

Day 050 publishes **Kagura Mask Star Dancer** at `/kagura/`: a mobile-first 3D shrine-stage rhythm/pose game about stepping through ordered kagura star marks, matching facing direction, mask state, and gohei height, striking on blue beat windows, and preserving balance/hush until the **Kagura Midpoint Blessing**.

The run followed the prompt-first workflow: the archived prompt was generated before implementation at `prompts/day-050.md`, then a fresh implementation subagent was started from that prompt. The implementation subagent timed out after creating partial Day 050 files, so the controller recovered the partial app, fixed runtime/UX issues, copied the selected app into the immutable release and public alias folders, and completed QA/validation before publish.

## Asset QA

Imagegen2 assets were generated for the dancer, shrine-stage background, pieces sheet, and action icon sheet, then inspected visually before integration.

- `kagura-stage.png`: portrait stage background is crop-safe, no text/watermark, and provides a strong moonlit shrine identity behind the WebGL stage.
- `kagura-pieces.png`: separated fox/oni/okame masks, star, gohei, lantern, bells, beat ring, shimenawa, heart, omamori, and blessing icons are readable with no text/watermark.
- `kagura-icons.png`: action icons for step/turn/gohei/strike/bell/mask/focus/balance/hush/strain/lantern/omamori are distinct and readable.
- `kagura-dancer.png`: the first optimized dancer copy had an opaque light rectangle when used as a Three.js plane. The controller alpha-cleaned the edge-connected background, re-exported the PNG as RGBA, copied it into app/release/alias, and re-smoked the route. The final desktop/mobile screenshots show the dancer as a clean cutout.

## QA notes

- Desktop Playwright route smoke exercised `/kagura/`: menu/tutorial, Start, WebAudio initialization, Step Forward, Turn Right, Raise Gohei, Star Focus visible overlay, Mask Swap during focus, canvas tile selection, forced result overlay, Restart, prompt pages, and console/request hygiene.
- Mobile Playwright route smoke used a 390x844 portrait viewport. Start stayed inside the first viewport; after gameplay started, HUD chips, commission card, 3D stage, helper, and all 16 action buttons were visible without scroll-dependent interaction. Touch targets measured at roughly 44px+.
- Prompt DOM probes passed for both `/games/050/prompt.html` and `/kagura/prompt.html`: semantic headings/lists, back-to-game link, no raw Markdown `<pre>` dump, no `ul > p` / `ol > p`, no direct nested lists, and no `<strong>`/`<b>` corruption inside `<code>`.
- A separate QA/review subagent flagged practical blockers while the controller was still fixing the route: missing screenshots, opaque dancer plane, and mobile/control concerns. The controller addressed the screenshot and dancer issues, added stronger hidden-state CSS for Star Focus, added debug handles for smoke-only state setup, and added a pointer-selection fallback for canvas tile taps.

## Lessons

- For 3D billboard characters, inspect the asset inside the actual WebGL scene, not only as a standalone PNG. Alpha/white-background problems are much more obvious on the stage plane.
- `hidden` can be accidentally overridden by a more specific `display: flex` rule. For custom overlays, add explicit `[hidden] { display: none; }` coverage on the same component class.
- Route-smoke screenshots should be captured before forced result overlays and after restart-state cleanup; otherwise a valid route smoke can accidentally produce a poor gallery thumbnail.
- Canvas tap-selection should have a deterministic fallback when raycasting misses on mobile/touch coordinates.
