# Day 045 Postmortem — Kendama Star Cup Juggler

## Summary

Day 045 shipped a mobile-first 2D kendama dexterity arcade at `/kendama/`. The implementation uses a self-contained canvas game with generated Imagegen2 art assets, visible touch controls, WebAudio wood-clack/bell cues initialized after Start, and debug handles for QA (`window.__day045Debug`, `window.__day045Audio`).

## What was generated

- Title: Kendama Star Cup Juggler
- Public route: `/kendama/`
- Immutable archive: `release/games/045/`
- Source app: `apps/day-045-kendama-star-cup-juggler/`
- Mode: 2D, portrait/mobile-first
- Core loop: tilt the handle, swing/pull the ball, catch requested cups, balance, collect star charms, and spike the finale for the Kendama Star Cup Ceremony.

## Assets

Imagegen2 assets were generated and optimized into the Day 045 app/release folders:

- `kendama-helper.png` — fox/kitsune toy-stall judge helper.
- `kendama-stall.png` — warm matsuri toy-stall background.
- `kendama-pieces.png` — kendama pieces and feedback sprites.
- `kendama-icons.png` — action/control icon sheet.

Source assets are archived under `release/games/045/assets/source/`. Visual QA inspected the playable assets and the route screenshots. The final implementation primarily uses the helper/background assets at runtime and draws gameplay pieces in canvas for crisp hitboxes and consistent mobile readability.

## QA notes

Route smoke covered the public alias `/kendama/` and `/kendama/prompt.html` through a static server with Playwright:

- Desktop viewport: 1280x900
- Mobile viewport: 390x844
- Menu/tutorial terms visible
- Start initializes gameplay and WebAudio (`enabled=true`, `ctx.state=running`)
- Required controls visible and wired: Tilt Left/Right, Swing Ball, Pull String, Cup Catch, Spike Catch, Toss Release, Balance Hold, Swap Cup, Star Focus, Pause, Restart, Audio, Prompt
- Control-effect probes changed game state and forced a win state through the debug handle
- Pause/resume/restart overlays were exercised
- Mobile first viewport fit verified: no page scroll, stage visible, 44px touch targets, controls bottom within 844px, required live HUD fields visible except Time intentionally hidden on phone to preserve prompt-required higher-priority fields
- Prompt page semantic DOM verified: no raw Markdown dump, valid heading/back-link structure, no malformed list nodes, no `<strong>` corruption inside `<code>`

Fixes made during QA:

- Repaired initial selector mismatches between HTML and game JS (`#stage`, `#startBtn`, HUD IDs, overlay IDs).
- Fixed prompt HTML Markdown conversion corruption for `release/games/001/**` / `release/games/044/**` code spans.
- Tightened mobile CSS to fit the whole play surface and controls in a 390x844 first viewport.
- Hid the ceremony banner when inactive so gallery/mobile screenshots are not clipped.
- Constrained desktop stage height so the 1280x900 route fits without scroll and produces a good gallery thumbnail.

## Lessons

- A canvas game can pass generic smoke while still failing startup if HTML/JS IDs drift; Day 045 needed explicit selector checks before route QA was meaningful.
- Mobile first-viewport fit needs both CSS metrics and visual inspection. Playwright click success alone is not enough because auto-scroll can hide overflow.
- Prompt HTML validation must explicitly check code spans containing glob patterns; raw Markdown converters can still corrupt `**` inside `<code>`.
- Generated assets help theme and polish, but final gameplay primitives should sometimes stay canvas-drawn for hitbox accuracy, crisp labels, and consistent control-to-motion feedback.
