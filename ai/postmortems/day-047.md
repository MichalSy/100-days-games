# Day 047 Postmortem — Tombo Dewline Glider

## Summary

Day 047 shipped a mobile-first 2D aerial dexterity arcade game at the public route `/tombo/`. The game uses a right-facing Imagegen2 dragonfly sprite over a warm portrait rice-terrace background, with ordered dew skims, reed perches, frog warning arcs, silk clearing, field-bell slowdown, Tombo Focus overlays, WebAudio cues, and a debug handle for deterministic QA.

## What went well

- The archived prompt was created first at `prompts/day-047.md`, then implementation proceeded from that prompt.
- Imagegen2 assets gave the day a distinct visual identity from the previous roofline, citrus-tree, and bonsai-themed days.
- Controller asset QA caught the lack of alpha in the first dragonfly output and a possible checkerboard-readability risk in the first pieces sheet; the dragonfly was alpha-cleaned and the pieces sheet was regenerated with a solid rice-paper background.
- Desktop and mobile route smoke verified menu/tutorial terms, start flow, WebAudio initialization, all named controls, score-changing mechanics, pause/resume, restart, prompt-page DOM, and a forced blessing terminal state.
- The final mobile 390x844 smoke kept HUD, objective, stage, helper, and all controls inside the first viewport with touch targets above 44px.

## Issues and recovery

- The implementation subagent result was too terse to trust by itself, so the controller inspected repo files, copied controller-inspected assets into app/release/alias locations, completed release wiring, and wrote the runtime game script directly.
- Initial mobile visual QA showed the `Tombo Focus` stage chip clipped at the right edge. The chip renderer now wraps stage chips onto a second row when needed.
- Initial route probe required the exact visible words `Pause` and `Restart` on the menu/tutorial surface; a tutorial bullet was added so those controls are visible before starting.
- Prompt HTML was generated with a small semantic Markdown renderer instead of a raw `<pre>` dump, including a back-to-game link and guards for malformed lists/code glob corruption.

## Follow-up improvements

- The daily implementation agent should return a fuller summary with exact files changed and validation outputs; a terse subagent result forces controller recovery work.
